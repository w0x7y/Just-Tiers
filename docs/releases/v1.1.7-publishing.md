## After approval

1. Commit the approved source and documentation changes and integrate them into
   `main`. Keep unrelated local indexing preferences separate.
2. Run the manual Modrinth dry-run workflow on the approved commit. The repository
   secret is configured; the local preparation environment has no Modrinth token,
   so authenticated Minotaur validation must run there before publishing.
3. Push the matching `v1.1.7` tag. The Release workflow verifies all seven targets,
   creates the GitHub prerelease and publishes seven Modrinth beta versions using
   the repository's `MODRINTH_TOKEN` secret.
4. Run the manual Sync Modrinth description workflow on the approved commit. It
   updates the summary, Markdown body and existing gallery captions. Page updates
   remain separate from version uploads.
5. Verify all seven uploaded versions, dependencies, release files and the live
   project copy. Report the release links. If an upload partially fails, rerun only
   the failed target jobs.

No tag, push, release upload or live Modrinth page update was performed before
maintainer approval.
